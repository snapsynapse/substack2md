# substack2md v2.2.0

Version 2.2.0 makes personal Substack archives more reliable to create and recover. The supported scope remains supplied post URLs and existing Markdown; publication crawling, other platforms, new export formats, and new interfaces are outside the maintenance scope.

## Changes

- Preserve spoken text when removing transcript labels, keep functional external query strings and fragments, and retain labels in publication-relative wikilinks.
- Reject empty and recognizable error/login captures and failed CDP navigation/evaluation. Buffer page events, bound capture waits, and close connections after each attempt.
- Let overwrite bypass resume, regenerate missing notes, and repair missing HTML sidecars without replacing existing Markdown. Pending markers make interrupted artifact pairs retryable.
- Report written/skipped/failed totals, return nonzero for failed captures, and cancel queued batch work on interruption.
- Validate configuration and numeric options, guard state/output symlinks, and reuse the archive index within each batch.
- Include regression fixtures and guide files in the Python source distribution and use current SPDX license metadata.
- Synchronize the website, README, machine summary, assistant guide, and maintenance procedure with actual behavior. Remove the unsupported archive-crawling claim and unverified hosted-conformance assertions.

## Upgrade notes

- New resume entries are JSON lines containing URL and relative output path. Version 2.2.0 still reads legacy URL-only entries. Older versions do not interpret the new entries; use `--no-resume` if temporarily downgrading.
- Requested paywall detection writes explicit nulls when status is unknown. Disabled detection omits those fields. Treat unknown as unknown, never as free content.
- CLI failures now produce nonzero exit status. Automation that previously ignored logged failures should handle that result.
- Default library pipeline results remain Path/None. Callers can opt into structured `ConversionResult` values with `detailed=True`.
- `--retries` retains its existing meaning: total attempts, including the first, with a minimum of one.

## Validation before publication

- Offline suite: 123 passed, one opt-in live test skipped, on Python 3.14.7.
- Pinned Ruff 0.16.1 lint/format and source-surface consistency checks pass.
- Candidate wheel and source distribution undergo package metadata, clean installation, console/module, and source-fixture checks; exact results and SHA-256 checksums are recorded in the local release-state bundle.
- Hosted Python 3.10-3.13 CI, signed commit/tag verification, and live website deployment must be verified for the final commit before delivery is declared complete.

## Limits

Capture heuristics cannot prove that every paid article is complete or that future Substack layouts will remain compatible. Images and embeds are external links, so only saved text is available offline. Current HTML fixtures are synthetic. Authenticated browser capture was not performed for this candidate.

Guide profile and byte checks do not establish safety or a current hosted GuideCheck level. Verify the exact served guide and compare its SHA-256 with the local copy before acting.
