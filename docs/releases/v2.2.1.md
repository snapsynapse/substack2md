# substack2md v2.2.1

Version 2.2.1 hardens links generated from captured HTML and makes the macOS CDP launcher refuse port conflicts. It is the first mitigation tranche from the November 22 security audit.

## Changes

- Neutralize unsupported link schemes while keeping HTTP(S), email and telephone links. Resolve relative links against the article URL and escape destinations for Markdown.
- Preserve an ordinary Markdown link when its label or destination cannot safely become an Obsidian wikilink.
- Exit when port 9222 is occupied instead of offering to terminate its listener.
- Clarify browser requirements, paywall metadata limits, release boundaries and HTTP credential behavior in documentation and CLI help.
- Include the threat model and scope documents in the Python source distribution.

## Upgrade and operating notes

Use a dedicated browser profile with only the needed Substack session, keep CDP on loopback, and close the dedicated browser when capture is finished. The launcher does not terminate an existing listener. Review the listener yourself before closing it.

The link safeguards apply to links generated from captured HTML. They do not sanitize article prose, imported Markdown or raw HTML sidecars, and they do not establish safety in every Markdown renderer. Paywall detection adds metadata; it does not block export, prove article completeness or grant sharing rights.

## Verification

Local validation: 140 tests passed and one opt-in public API test skipped. Pinned Ruff lint and formatting, shell syntax, local guide parity and release-surface checks passed. Synthetic inputs reproduce the original unsafe-link and wikilink cases and exercise the fixes. The occupied-port branch was checked without launching a browser. Wheel installation and exact-release CI results are recorded with the release artifacts and GitHub Actions.

## Remaining security work

The broader audit is not closed. Imported Markdown handling, capture size and concurrency limits, URL admission, URL log redaction, dependency constraints and ambient HTTP authentication remain open. Requests may load matching `.netrc` credentials or use configured proxies. Installed dependency versions must be audited in the actual consumer environment; this patch does not upgrade them. No authenticated browser acceptance or full hosted conformance assessment was performed.

The assistant guide remains version 1.0.2, profile 0.3.0, applicable to substack2md 2.2.x. Its existing v2.2.0 provenance reference is retained because those exact guide bytes are unchanged. Local parity does not establish hosted conformance or publisher authenticity.
