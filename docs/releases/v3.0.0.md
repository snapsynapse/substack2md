# substack2md v3.0.0

Released November 22, 2026 (America/Denver). This is the last planned release. Critical security and breakage fixes remain in scope until retirement is announced; optional maintenance may be considered before then. The repository is not retired.

## Upgrade

Python 3.11.5 or newer is required. Recreate older virtual environments and reinstall the dependencies. Upgrade pip and setuptools first as shown in the README; older Python installers bundle vulnerable setuptools. The build and setup floor is setuptools 84.1.0. Source installations can use the tested versions in `constraints-runtime.txt`. Existing environments do not acquire the fixes merely by changing the version file. Homebrew delivery and installation verification remain a separate tap update. This project is not distributed through PyPI.

Post URLs must use HTTPS without embedded credentials or nonstandard ports. Substack URLs use `/p/slug`; custom publication paths remain supported. The CLI only accepts loopback CDP hosts, at most eight workers, and at most 8 MiB of captured HTML.

## Security and correctness

Public paywall metadata requests now use a fresh HTTP session without environment proxies, netrc authentication or redirects. Unknown metadata remains unknown. CLI progress and failure logs omit article URLs and raw transport exception messages. Captured HTML is size-checked before parsing and bounded in the browser-side extraction expression. IPv6 loopback CDP discovery uses a bracketed authority.

Updated dependency floors, tested runtime constraints, immutable CI action pins and dependency auditing accompany the link-safety and launcher safeguards shipped in v2.2.1. The macOS helper only advises restarting its dedicated browser instance.

## Limits and verification

A dedicated local browser profile and a private local archive remain the supported operating model. URL admission is not a DNS or redirect sandbox, and capture size limits are not process isolation or a parser deadline. Imported Markdown remains untrusted content-preserving input. Optional HTML sidecars can contain active content. Library error objects and caller logs may contain private data.

## Pending browser gates

Publication was authorized with the following acceptance checks still pending:

- Dedicated-profile browser capture of a public Substack post and a custom publication domain, including loopback binding, output and failure behavior.
- Rendered accessibility testing, including axe/WCAG checks and keyboard/device acceptance.
- Browser or Markdown-renderer execution checks for generated link behavior.

These checks have not passed and are not established by the offline CDP fixtures, parser tests, public API smoke test, hosted assessments or CI. No private subscriber capture was performed for this release.

## Known hosted header warnings

Hosted GuideCheck evaluated the deployed guide at Level 3 with zero blocking findings and two nonblocking warnings:

- The served guide lacks `X-Content-Type-Options: nosniff`.
- The served guide lacks `Strict-Transport-Security` (HSTS).

The repository provides `docs/_headers`, but GitHub Pages does not apply that file. The warnings remain open; this release does not change hosting or claim that the headers are present. GuideCheck Level 3 does not prove publisher identity, dependency safety, browser acceptance or accessibility conformance.

## Verification and distribution

The release workflow requires all five Python CI jobs (3.11.5 and current 3.11 through 3.14), tests, pinned lint, dependency audit, clean wheel installation and deployed-byte verification before publication. Assets include a wheel, Python source distribution, complete source snapshots, these notes and SHA-256 checksums. This project is distributed through GitHub Releases and a separately maintained Homebrew tap, not PyPI.
